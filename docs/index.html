Dashboards BI — Mudecorp International SA

Trois dashboards Power BI construits sur des données fictives de 01/01/2024 à 31/12/2027 : un suivi financier complet (flux, budget vs réalisé), les ventes (commandes, produits, vendeurs) et les ressources humaines (paie, absences, formations). Le tout généré par scripts SQL, exporté en CSV et modélisé en format Power BI Project (.pbip) moderne.

MySQL / MariaDB 10.4 Power BI Desktop Format .pbip TMDL DAX 29 exports CSV

Les trois dashboards

Chaque dashboard est un projet Power BI (.pbip) prêt à ouvrir, avec 3 pages et des indicateurs clés.

Finance — bi_finance

~11 000 transactions, 65 clients, 15 comptes, budget vs réalisé. 3 tables, 8 mesures DAX, 14 visuals.

  • Vue d'ensemble — 4 KPI (Revenus, Dépenses, Résultat, Marge), courbes Revenus vs Dépenses, donut de répartition, budget vs réel
  • Revenus — Top clients, secteurs, croissance du chiffre d'affaires
  • Dépenses & Budget — Réalisé vs budget par groupe, taux de réalisation

Ventes — bi_ventes

~7 400 commandes, ~22 000 lignes, 35 produits, 12 vendeurs.

  • Vue d'ensemble — 4 KPI (CA, Marge, Commandes, Panier moyen), courbes CA, gauge taux de marge
  • Produits & Catégories — CA par catégorie, top produits, stock avec alerte rupture
  • Vendeurs & Clients — CA par vendeur, matrice vendeur × mois, répartition par canal

RH — bi_rh

120 employés, 4 464 bulletins de paie, absences, formations.

  • Vue d'ensemble — 4 KPI (Effectif, Masse salariale, Salaire moyen, Réalisation budget)
  • Effectifs — Effectif par département, contrat, genre, ancienneté
  • Absences & Formations — Jours perdus, matrice absences, coût et thèmes de formation

Le modèle Power BI (.pbip)

Le dossier MudecorpFinance.pbip/ est un projet Power BI au format texte moderne : le modèle sémantique (TMDL) contient 3 tables — FluxFinancier, Calendrier, BudgetVsReel — chargées depuis les exports CSV, reliées par une relation Calendrier → FluxFinancier (joinOnDateBehavior: datePartOnly), avec 8 mesures DAX.

Mesures DAX

Les mesures réellement implémentées dans le modèle sémantique du dashboard Finance.

Modèle sémantique (implementées dans FluxFinancier)

Total Revenus = CALCULATE(SUM(FluxFinancier[Montant]), FluxFinancier[TypeFlux] = "REVENU", FluxFinancier[Statut] = "VALIDE") Total Dépenses = CALCULATE(SUM(FluxFinancier[Montant]), FluxFinancier[TypeFlux] = "DEPENSE", FluxFinancier[Statut] = "VALIDE") Résultat Net = [Total Revenus] - [Total Dépenses] Marge Nette % = DIVIDE([Résultat Net], [Total Revenus], 0) Nb Transactions = COUNT(FluxFinancier[TxId]) Panier Moyen = DIVIDE([Total Revenus], [Nb Transactions]) Revenus Mois Précédent = CALCULATE([Total Revenus], PREVIOUSMONTH(Calendrier[DateId])) Variation Revenus % = DIVIDE([Total Revenus] - [Revenus Mois Précédent], [Revenus Mois Précédent], 0)

Dashboard Ventes (référence)

Chiffre d'affaires = SUM(v_ventes_detail[montant_ligne]) Marge brute = SUM(v_ventes_detail[marge_brute]) Taux de marge % = DIVIDE([Marge brute], [Chiffre d'affaires], 0) Nb Commandes = DISTINCTCOUNT(v_ventes_detail[commande_id]) Panier moyen = DIVIDE([Chiffre d'affaires], [Nb Commandes]) CA Mois Précédent = CALCULATE([Chiffre d'affaires], PREVIOUSMONTH(v_ventes_detail[date_commande]))

Dashboard RH (référence)

Effectif = COUNT(v_effectif[employe_id]) Masse salariale brute = SUM(v_paie_mensuelle[masse_salariale_brute]) Salaire moyen = DIVIDE([Masse salariale brute], [Effectif], 0) Nb Absences = SUM(v_absences_mensuelles[nb_absences]) Taux d'absentéisme % = DIVIDE([Jours perdus], [Effectif] * 260, 0) Heures de formation = SUM(v_formations[duree_heures]) Coût formation = SUM(v_formations[cout])

Installation et utilisation

De la génération des données à l'ouverture du dashboard dans Power BI Desktop.

0. Tout régénérer en 1 commande

# WSL / Linux ./automatisation.sh # Windows (double-clic) automatisation.bat
Compte ~7 minutes : le script démarre MariaDB si besoin, recrée les 3 bases et exporte les 29 CSV. Les montants varient à chaque exécution (génération aléatoire RAND()).

Ouvrir le dashboard (.pbip)

Le format .pbip est un aperçu : il nécessite Power BI Desktop de juillet 2025 ou plus récent avec les fonctionnalités d'aperçu activées.

  1. Power BI Desktop → Fichier → Options et paramètres → Options
  2. Onglet Fonctionnalités en préversion → activer Power BI project (.pbip) save option et Store semantic model using TMDL format
  3. OK → redémarrer Power BI Desktop
  4. Fichier → Ouvrir → sélectionner le fichier MudecorpFinance.pbip dans le dossier MudecorpFinance.pbip/
  5. Les données se chargent depuis les CSV de csv/finance/ (aucun pilote MySQL requis)
N'ouvrez pas un .pbix : le seul fichier ouvrable est le .pbip (dossier contenant le fichier du même nom). Le .pbix binaire ne peut être créé que par Power BI Desktop lui-même (Fichier → Enregistrer sous).

Reconnecter à MySQL (optionnel)

Les exports CSV permettent un import direct. Pour utiliser la base MySQL à la place :

  1. Démarrer MySQL : XAMPP Control Panel → Start sur MySQL
  2. Power BI Desktop → Obtenir des données → Base de données MySQL
  3. Serveur : localhost:3306 — Base : bi_finance — Utilisateur root (sans mot de passe)
  4. Si l'erreur « La valeur demandée 'None' est introuvable » apparaît : MariaDB n'est pas compatible avec le connecteur MySQL de Power BI — utiliser plutôt les CSV ou le connecteur ODBC

Recréer les bases depuis zéro

mysql -u root < 01_schema.sql # base bi_finance (schéma) mysql -u root < 02_data.sql # base bi_finance (données + vues) mysql -u root < 03_ventes.sql # base bi_ventes (tout) mysql -u root < 04_rh.sql # base bi_rh (tout)

Les scripts sont réexécutables : ils réinitialisent et régénèrent les données.
